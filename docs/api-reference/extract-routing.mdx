`extractRouting` is the core function of the library. It reconciles an address and memo into a canonical routing result.

## Function Signatures
<CodeGroup>

```typescript TypeScript
function extractRouting(input: RoutingInput): RoutingResult
```

```go Go
func ExtractRouting(input RoutingInput) RoutingResult
```

```dart Dart
RoutingResult extractRouting(RoutingInput input)
```

</CodeGroup>

## Input: `RoutingInput`

| Field | Type | Description |
|---|---|---|
| `address` | `string` | The destination address (G, M, or C). |
| `memoType` | `string` | (Optional) `ID`, `TEXT`, `HASH`, or `RETURN`. |
| `memoValue` | `string` | (Optional) The raw memo value. |
| `allowHashRouting` | `boolean` | (Optional) When enabled, accepts 32-byte hex memos for `MEMO_HASH` and `MEMO_RETURN`. Defaults to `false`. |
| `minSeverityLevel` | `'info' \| 'warn' \| 'error'` | (Optional) Drops warnings below this severity. Defaults to `info` (keep all). See [Warning System](/concepts/warning-system). |

## Output: `RoutingResult`

| Field | Type | Description |
|---|---|---|
| `address` | `string` | The canonical base G-address. |
| `routingId` | `string` | The extracted 64-bit ID (or empty string). For hash routing, the normalized lowercase 64-character hex string. |
| `routingSource` | `string` | The source of the routing ID (e.g. `memo`). |
| `warnings` | `Warning[]` | List of warnings encountered. |
| `destinationError` | `string` | Error code if the destination is invalid. |

## Hash Routing

By default, `MEMO_HASH` and `MEMO_RETURN` memos are flagged as `UNSUPPORTED_MEMO_TYPE` (with `context.memoType`). With `allowHashRouting` on, a malformed hash is flagged as `MEMO_TEXT_UNROUTABLE`. Many cross-chain bridges and institutional custodians use 32-byte hex hashes as deposit identifiers. Set `allowHashRouting` to `true` to enable these memos.

When enabled, the memo must be a valid 32-byte hex string (64 hexadecimal characters). If valid, `routingSource` is set to `memo` and `routingId` is the normalized lowercase hex string.

```typescript
const result = extractRouting({
  address: "GADDRESS...",
  memoType: "HASH",
  memoValue: "ABCDEF0123456789ABDEF0123456789ABDEF0123456789ABDEF0123456789",
  allowHashRouting: true,
});

// result.routingSource === "memo"
// result.routingId === "abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789"
```

## SEP-0029 Memo Requirement (TypeScript)

Exchanges and custodial services often set `config.memo_required` (or `config.requiring_memo`) in their account data per [SEP-0029](https://github.com/stellar/stellar-protocol/blob/master/ecosystem/sep-0029.md). A payment sent to such an account without a memo usually ends up as a stuck deposit.

`extractRoutingAsync` runs `extractRouting` and then checks the destination against Horizon. When the account requires a memo but no routing ID was extracted, it appends:

```typescript
{ code: "MISSING_REQUIRED_MEMO", severity: "error", message: "..." }
```

```typescript
import { extractRoutingAsync, fetchMemoRequirement } from "stellar-address-kit";

const result = await extractRoutingAsync(
  { destination: "GADDRESS...", memoType: "none", memoValue: null, sourceAccount: null },
  { horizonUrl: "https://horizon.stellar.org", timeoutMs: 5000 }
);

// Or check an account directly:
const required = await fetchMemoRequirement("GADDRESS...", {
  horizonUrl: "https://horizon-testnet.stellar.org",
});
```

| Option | Type | Description |
|---|---|---|
| `horizonUrl` | `string` | Horizon base URL. Defaults to `https://horizon.stellar.org`. |
| `fetch` | `FetchLike` | Custom `fetch` implementation. Defaults to `globalThis.fetch`. |
| `timeoutMs` | `number` | Request timeout in milliseconds. Defaults to `10000`; `0` disables it. |
| `signal` | `AbortSignal` | Optional caller abort signal. |
| `fetchMemoRequirement` | `(accountId) => Promise<boolean>` | Replaces the Horizon lookup, for example with a cache or an indexer. |
| `allowHashRouting` | `boolean` | Forwarded to `extractRouting`. |

Behaviour:

- No lookup is made when the synchronous result already has a routing ID (including every M-address), has no base account (for example a contract sender), or reports a destination error.
- A Horizon `404` (unfunded account) counts as "memo not required".
- Lookup failures fail open: network errors, timeouts, non-2xx responses and unreadable bodies return the synchronous result unchanged. `fetchMemoRequirement` on its own rejects with `MemoRequirementLookupError` in these cases.
- Values are base64-decoded, and `1` or `true` (case-insensitive) mean the memo is required.
